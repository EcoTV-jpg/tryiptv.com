# Internal Linking and Information Architecture

## Architecture
Map:
- home
- commercial hubs
- learning hubs
- device/platform hubs
- support/troubleshooting hubs
- evidence/experience hubs

## Link checks
For important URLs:
- number and quality of contextual inbound links
- nav/footer/breadcrumb support
- click depth
- anchor relevance
- orphaning
- links from high-authority internal pages
- links to redirected/noncanonical URLs
- duplicated boilerplate link blocks

## Intent-aware linking
Links should help the user move:
Learn → choose → trial/pricing
Device → compatible player → setup → troubleshooting
Problem → diagnosis → relevant setup/service page

Do not force every page to link to every money page.

## Anchor text
Prefer descriptive, natural anchors.
Avoid:
- massive exact-match repetition
- generic “click here” everywhere
- misleading anchor/target mismatch

## Hubs
A hub should add orientation and selection value, not just list links.

## Finding bar
“Page has only 3 internal links” is not a finding by itself.
Explain discoverability, hierarchy, orphan risk, or user-path impact.
