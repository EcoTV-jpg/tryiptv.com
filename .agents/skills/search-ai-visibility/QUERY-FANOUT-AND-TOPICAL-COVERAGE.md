# Query Fan-out and Topical Coverage

Query fan-out does not justify mass page creation.

## Build a query/task graph

For a priority query, classify related needs into:
- prerequisite question
- comparison criterion
- setup/use step
- troubleshooting branch
- commercial decision
- evidence question
- local/device/contextual constraint

Then decide:
- same page section
- separate indexable URL
- non-indexable support content
- not worth covering

## Separate URL test
Create a URL only when:
1. the user task is distinct;
2. the SERP/search experience is likely distinct;
3. the page can have substantial unique value;
4. internal linking can define its place;
5. it is not a permutation doorway page.

Mandatory:
**What is the one thing this page will solve better than any URL that already exists?**

## Coverage quality
A topic cluster is strong when pages cooperate:
- parent/hub defines the problem space
- child pages solve distinct intents
- links express relationships
- repeated boilerplate is minimized
- facts remain consistent
